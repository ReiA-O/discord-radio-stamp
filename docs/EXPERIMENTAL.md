# 実験運用について

最初の開催予定は **2026年10月24日（土）04:00 JST** です。以後は00:00・04:00・07:00・12:30・22:00 JSTの既存5枠を使用する計画です。準備済み・配備済み・実稼働開始は別の状態で、ソースの公開だけではBotは起動しません。

2026-10-21現在、週間ランキングは本番OFF配備済みです。10分前通知と開始ゲートはローカル実装・検証までで、本番反映は未実施。開始用sidecar/wrapper・有効化設定・Cronも未設置で、初回04:00へ向けた稼働予約は未完了です。実稼働・実通知はまだ開始していません。

初回04:00枠は03:30にVCの接続を開き、03:50にメンションなしで案内する設計です。10月24日00:00枠や、それ以前の開催・副作用を開始しない開始ゲートが必要です。開始ゲートの実装・配備・最終確認が完了してから稼働準備完了とします。

ローカルの開始ゲートは、Scheduleの`not_before`と、非公開の実設定に隣接する非秘密`launch-gate.json`の`first_session_at`を照合します。どちらも初回開催のJST日時を使い、開場可能になるのはその30分前です。HTTP/CLIは開始前に実設定や秘密providerを読みません。さらに配備側の信頼するwrapperも、有効化設定と開始時刻の両方を満たす必要があります。sidecar無しは既存構成と互換動作になるため、sidecarだけを唯一の開始防止手段にしません。開始前に保存された古い開催・副作用も処理対象から除外し、旧記録を削除・書換えせず残します。

## 通常の流れ

- 開催30分前に同じVCを接続できる状態へ開きます。VCを毎回削除して作り直しません。
- 開始10分前から予定開始時刻より前の間に、VCが実際に開場済みかを確認して1回通知します。開始時刻以降は未来形の案内を送らず、開場失敗時に開場済みと通知しません。
- 07:00・12:30・22:00枠の通知だけに`@here`を付けます。00:00・04:00枠にはメンションを付けません。判定基準は通知した時計時刻ではなく開催枠です。
- 最初の開始コマンド成功から9分後に予告、10分後に閉場して残っている参加者を切断します。誰も開始しなかった場合は予定時刻30分後に閉場します。
- 参加回数とJST参加日数は別集計です。同じ開催の二重参加は数えません。週間ランキングはJST月曜00:00以上から翌月曜00:00未満の開催分を翌月曜07:00に発表する設計です。

## 実機で未確認のこと

一般メンバーによる参加受付、Windows/iPhoneでのカード保存、予告後の実VC切断、同時に複数人が操作する場合は未確認です。週次ランキングと開始10分前通知の実Discord投稿、実際のメンション通知、継続した定時運転も、隔離試験の成功だけでは確認済みになりません。

実験中は、受付・画像・通知・切断が想定どおり動かない可能性があります。不具合があれば運営者が停止し、現DBと未確定の送信結果を保全します。送信結果不明の通知を自動で再投稿・再メンションしません。後から記録が増えたDBを、古いバックアップへ無条件に戻しません。

## 停止と復旧

運用者は、公開領域外の有効化設定と定時起動を停止できる手順を、実環境ごとに準備してください。実行中workerは所定の終了経路で止め、動作中のDB/WAL/SHMを削除しないでください。停止後は対象・現在の記録・送信台帳・バックアップを照合して復旧を判断します。この保存用リポジトリには、実環境の設定・認証情報・停止操作へのアクセスは含めません。

現在のworkerは読み込んだ設定を保持し、停止設定を随時再読込しません。新しいHTTP/CLIを停止しても、既に実行中のworkerは最大55秒とREST timeout約2秒の終了待ちがあり得ます。即時停止と断定せず、対象process/DB接続が終了したことを確認します。

実際の公開対象・告知先・権限は運用者の確認事項です。他カテゴリやサーバー全体の権限・年齢制限を、このBotの設定と一緒に変更しません。
